## 클로드에 갑자기 ‘보이지 않는 워터마크’가 들어간 이유

AI 업계에서 **워터마크(Watermark)** 문제가 새로운 논쟁거리로 떠올랐습니다.

이번 논란의 중심에는 앤트로픽(Anthropic)의 생성형 AI 서비스 **클로드(Claude)**가 있습니다. 앤트로픽은 2026년 8월부터 클로드가 생성하는 텍스트에 사람이 눈으로 확인할 수 없는 형태의 **텍스트 워터마크**를 적용하기 시작했습니다.

단순히 화면 구석에 ‘AI 생성’이라는 문구를 붙이는 방식은 아닙니다. 일반 사용자가 문장을 읽었을 때는 워터마크가 적용됐는지 거의 알아차릴 수 없지만, 특정 방식으로 텍스트를 분석하면 **클로드가 해당 문서 작성에 관여했을 가능성**을 판별할 수 있도록 설계된 기술입니다.

앤트로픽이 이런 기능을 도입한 가장 직접적인 배경은 **유럽연합(EU) AI법(AI Act)**입니다.

EU AI법 제50조와 관련된 생성형 AI 투명성 의무는 **2026년 8월 2일**부터 적용되기 시작했습니다. EU 집행위원회는 생성형 AI 제공업체가 AI가 생성하거나 조작한 콘텐츠를 식별할 수 있도록 **기계 판독 가능한 표시(machine-readable marking)**를 적용하도록 요구하고 있습니다. 

앤트로픽은 2026년 8월 14일 공개한 공식 설명에서 클로드의 텍스트 워터마크 역시 이 규정을 준수하기 위한 것이라고 밝혔습니다. 앤트로픽은 다른 주요 AI 기업들과 함께 2026년 7월 EU의 AI 생성 콘텐츠 투명성 관련 행동규범에 참여했습니다. 

정리하면 현재 상황은 다음과 같습니다.

| 구분 | 내용 |
|---|---|
| 대상 서비스 | **앤트로픽 클로드(Claude)** |
| 핵심 변화 | 생성 텍스트에 **비가시성 워터마크** 적용 |
| EU 규정 적용 시점 | **2026년 8월 2일** |
| 앤트로픽 상세 설명 공개 | **2026년 8월 14일** |
| 도입 목적 | **EU AI법 투명성 규정 대응** |
| 워터마크 형태 | 사람이 볼 수 없는 **통계적·암호학적 패턴** |
| 숨은 문자 삽입 | **아님** |
| 사용자 개인정보 포함 | **아님** |
| 적용 범위 | 우선 신규 모델, 향후 기존 모델 확대 |
| 지역 | 현재 사실상 **글로벌 적용** |

문제는 규제 취지 자체보다 **워터마크가 AI 사용의 흔적을 어디까지 남겨야 하느냐**는 부분에서 발생했습니다.

앤트로픽 입장에서는 AI 생성물을 식별할 수 있도록 만드는 기술적 안전장치이지만, 일부 사용자들은 이를 전혀 다르게 받아들이고 있습니다.

특히 개발자와 기업 문서 작성자들에게는 단순한 기능 변경이 아니라 **자신이 만든 결과물의 저작·책임·AI 사용 여부를 다른 사람이 판단할 수 있게 만드는 변화**로 느껴질 수 있기 때문입니다.


## 워터마크라고 해서 숨겨진 문자가 삽입되는 것은 아닙니다

이번 논란에서 가장 먼저 구분해야 할 부분이 있습니다.

클로드의 워터마크는 우리가 흔히 생각하는 파일 속의 **숨은 문자, 특수문자, 메타데이터**와는 다릅니다.

예를 들어 AI가 작성한 문장 끝에 사람이 볼 수 없는 특수문자를 집어넣거나, 복사하면 따라오는 코드를 몰래 삽입하는 방식이 아닙니다.

앤트로픽은 공식적으로 **“텍스트에 어떤 문자도 추가하지 않으며 숨은 문자도 존재하지 않는다”**고 설명했습니다. 

핵심은 LLM이 다음 단어를 선택하는 과정에 있습니다.

대규모언어모델은 문장을 한 번에 완성하지 않습니다. 앞에 있는 문맥을 토대로 다음에 올 수 있는 여러 후보 가운데 하나를 선택하는 과정을 반복합니다.

예를 들어 다음과 같은 문장이 있다고 가정해 보겠습니다.

> 오늘 날씨는 춥고 ______.

빈칸에 ‘흐렸다’, ‘쌀쌀했다’, ‘바람이 불었다’처럼 문맥적으로 자연스러운 여러 표현이 존재할 수 있습니다.

기존 LLM에서도 이런 후보 가운데 최종 단어를 선택하는 과정에는 일정 수준의 확률성과 무작위성이 들어갑니다.

클로드의 워터마크는 이 **무작위성을 만들어내는 방법에 일정한 규칙을 넣는 방식**입니다.

앤트로픽 설명에 따르면 기술적으로는 **Google DeepMind가 2024년 발표한 SynthID-Text 계열 기술**을 사용합니다. 

단순화하면 다음과 같은 구조입니다.

| 일반적인 텍스트 생성 | 워터마크 적용 생성 |
|---|---|
| 후보 단어 여러 개 계산 | 후보 단어 여러 개 계산 |
| 확률적으로 단어 선택 | 확률적으로 단어 선택 |
| 일반 난수 활용 | **키와 이전 단어를 이용한 난수 패턴 활용** |
| 생성 흔적 확인 어려움 | 긴 문장에서 특정 통계적 패턴 확인 가능 |

중요한 것은 워터마크 때문에 클로드가 이상한 단어를 억지로 사용하는 것은 아니라는 점입니다.

예를 들어 정확한 답이 하나뿐인 상황에서 워터마크를 남기기 위해 일부러 틀린 단어를 선택하는 구조가 아닙니다.

앤트로픽은 내부 테스트와 SynthID 관련 연구를 근거로 워터마크가 **텍스트 품질, 창의성, 가독성 등에 실질적인 영향을 주지 않는다**고 설명하고 있습니다. 추가 토큰도 발생하지 않아 사용자 가격에도 영향을 주지 않는다는 입장입니다. 

즉 사용자가 눈으로 보면,

**워터마크가 적용된 문장과 적용되지 않은 문장을 구별하기 어렵습니다.**

그 대신 워터마크 검출 키를 가진 시스템이 충분한 길이의 문장을 분석하면,

**“이 텍스트를 클로드가 작성하는 데 관여했을 가능성이 어느 정도인가”**

를 통계적으로 판단할 수 있게 됩니다.

## 그런데 왜 사용자들은 구독까지 취소하고 있을까요?

기술적인 설명만 보면 큰 문제가 없어 보일 수도 있습니다.

개인정보가 들어가는 것도 아니고, 이름이나 계정 정보가 기록되는 것도 아니며, 글의 품질에도 영향을 주지 않는다고 앤트로픽이 설명하고 있기 때문입니다.

하지만 실제 사용자들이 우려하는 것은 조금 다른 문제입니다.

**“AI가 사용됐다는 사실 자체가 결과물에 남는 것 아니냐”**는 것입니다.

AI타임스는 2026년 8월 15일 보도에서 앤트로픽의 워터마크 도입 발표 이후 X 등 소셜미디어에서 **클로드 구독을 취소했다는 사용자들의 글이 잇따르고 있다**고 전했습니다. 

대표적인 사례를 보면 왜 논란이 커졌는지 쉽게 이해할 수 있습니다.

미국 공공정책 분야에서 일하는 한 사용자는 자신이 작성한 문서를 클로드에 넣어 **맞춤법이나 인용 표현 정도만 수정했는데도 AI 흔적이 남을 가능성**을 우려했다고 합니다.

결국 그는 유료 서비스인 **Claude Max 구독을 중단하고 Cursor와 Grok 등 다른 서비스를 사용하는 방향으로 전환했다고 밝혔습니다.** 

기업 문서 작성에 클로드를 활용하던 AI 컨설턴트 역시 비슷한 이유로 구독을 취소했다고 밝혔습니다.

사용자가 가장 우려하는 상황을 구분해 보면 다음과 같습니다.

| 사용 방식 | 사용자 입장에서 느끼는 문제 |
|---|---|
| AI에게 문서 전체 작성 요청 | AI 생성 표시를 어느 정도 예상 가능 |
| 초안 일부 작성 요청 | AI와 사람의 기여도 구분 어려움 |
| 사람이 작성 후 AI가 문장 수정 | **사람이 쓴 글도 AI 작성물처럼 보일 우려** |
| 맞춤법·문법 검사 | 단순 도구 사용인데 AI 사용 흔적 발생 우려 |
| 번역 | AI가 대부분의 단어를 선택하므로 워터마크 가능 |
| 프로그래밍 코드 작성 | 고객사·회사 규정과 충돌 가능성 우려 |
| 코드 주석 작성 | 자연어 영역에 워터마크 적용 가능 |
| 기업 보고서 편집 | 계약·컴플라이언스 문제 우려 |

특히 기업 사용자에게는 **AI를 썼느냐 안 썼느냐**가 단순한 취향 문제가 아닐 수 있습니다.

일부 회사나 고객은 생성형 AI 사용을 제한하거나, AI가 작성한 코드 또는 문서에 대해 별도의 검증 절차를 요구합니다.

예를 들어 개발자가 직접 수백 줄의 코드를 작성한 뒤 클로드에게 변수 이름이나 주석을 수정하도록 요청했다고 가정해 보겠습니다.

결과물의 대부분은 개발자가 직접 작성했더라도 외부의 워터마크 분석에서 클로드의 관여 가능성이 나타난다면,

“이 코드는 AI가 만든 것인가?”

라는 문제가 발생할 수 있습니다.

바로 이 지점에서 **AI 생성(AI-generated)**과 **AI 보조(AI-assisted)**를 어떻게 구분할 것이냐는 새로운 문제가 등장합니다.


## 개발자들이 특히 민감하게 반응하는 이유는 ‘저작권’보다 계약과 증명의 문제입니다

이번 논란에서 가장 민감하게 반응하는 집단 중 하나가 **소프트웨어 개발자**입니다.

AI 코딩 도구는 이미 개발자의 일상적인 생산성 도구로 자리 잡았습니다.

코드 전체를 작성시키지 않더라도 다음과 같은 업무에 AI가 광범위하게 활용됩니다.

- 코드 리팩터링
- 변수명 변경
- 테스트 코드 작성
- 주석 작성
- 오류 메시지 분석
- SQL 쿼리 수정
- 정규표현식 생성
- API 사용법 확인
- 문서화
- 코드 리뷰

그런데 고객과의 계약에 **AI 생성 코드 사용 금지**, **외부 AI 도구 사용 시 사전 승인**, **AI 생성 결과물 공개 의무** 같은 조항이 들어 있다면 상황이 복잡해질 수 있습니다.

AI타임스 보도에 따르면 체코의 프리랜서 개발자와 몬테네그로의 소프트웨어 엔지니어 등 일부 개발자는 고객에게 전달하는 코드에서 AI 관련 표시가 검출될 경우 **저작자 여부나 계약 문제로 이어질 가능성**을 우려해 클로드 구독을 중단했다고 밝혔습니다. 

물론 여기에서 중요한 사실이 있습니다.

**클로드 워터마크 자체가 저작권이나 소유권을 결정하지는 않습니다.**

앤트로픽 역시 공식 설명에서 워터마크는 클로드가 콘텐츠 생성 또는 처리에 관여했을 가능성을 확인하기 위한 기술일 뿐이며, **결과물의 소유권·저작성·법적 책임을 결정하거나 사용자의 권리를 변경하지 않는다**고 명확하게 밝히고 있습니다. 

따라서

**“워터마크가 검출됐다 = 앤트로픽이 저작권을 갖는다”**

또는

**“워터마크가 검출됐다 = 사용자는 저작자가 아니다”**

라고 해석하는 것은 잘못된 이해입니다.

하지만 실무에서는 법적 의미와 조직의 내부 판단이 항상 같지는 않습니다.

예를 들어 회사에서 AI 사용을 금지하고 있다면 법적으로 저작권 문제가 없더라도 **사내 정책 위반**이 될 수 있습니다.

고객 계약에서 AI 사용 여부 공개를 요구한다면 역시 문제가 될 수 있습니다.

따라서 개발자들이 우려하는 핵심은 워터마크가 직접 저작권을 박탈한다기보다,

**“AI 관여 여부를 제3자가 판단할 수 있게 되면서 새로운 증명과 분쟁의 가능성이 생긴다”**

는 데 있다고 보는 것이 더 정확합니다.

흥미로운 점은 실제 **프로그램 코드에는 자연어보다 워터마크가 훨씬 적게 적용될 가능성이 높다**는 점입니다.

앤트로픽은 코드에서는 정확한 토큰 선택이 필요한 경우가 많아 워터마크를 넣을 수 있는 선택지가 제한된다고 설명합니다.

예를 들어 다음과 같은 코드에서

`2 + 2 = 4`

정답 대신 워터마크를 위해 다른 값을 출력할 수는 없습니다.

마찬가지로 함수명이나 문법처럼 정확성이 필요한 부분에서도 임의로 토큰을 변경하기 어렵습니다.

따라서 실제 코드보다는 **코드 주석, 설명문, README, 문서화 영역**처럼 표현의 선택지가 많은 곳에서 워터마크가 나타날 가능성이 상대적으로 높습니다. 


## ‘맞춤법만 고쳐도 AI 글이 되나’가 이번 논쟁의 핵심입니다

앤트로픽의 설명을 보면 사용자들의 우려가 다소 과장된 부분도 있습니다.

사람이 작성한 글을 클로드가 단순히 맞춤법만 수정했다면 전체 글에 강력한 워터마크가 남는 구조는 아닙니다.

워터마크는 기본적으로 **클로드가 직접 선택한 단어에만 적용될 수 있기 때문**입니다.

예를 들어 사람이 1,000단어짜리 글을 작성한 뒤 클로드가 오타 5개만 수정했다면, 클로드가 실제 선택한 단어가 너무 적기 때문에 충분한 워터마크 패턴을 검출하기 어려울 수 있습니다.

앤트로픽도 단순 교정 작업에서는 수정되는 단어 자체가 적기 때문에 **워터마크를 검출하기 어려울 수 있다**고 설명합니다. 

반대로 사용자가 초안만 작성하고 클로드가 문장을 대부분 다시 써준다면 상황은 달라집니다.

| 클로드 사용 방식 | 워터마크 검출 가능성 |
|---|---|
| 오타 1~2개 수정 | 매우 낮을 가능성 |
| 맞춤법·구두점만 교정 | 상대적으로 낮음 |
| 문장 일부 자연스럽게 수정 | 수정 범위에 따라 달라짐 |
| 전체 문장 재작성 | 높아질 수 있음 |
| 새로운 문단 생성 | 상대적으로 높음 |
| 장문의 글 전체 생성 | 높은 편 |
| 번역 | **높아질 수 있음** |
| 정확성이 필요한 프로그램 코드 | 상대적으로 낮음 |
| 코드 주석·설명 | 일반 코드보다 높을 수 있음 |

특히 **번역**은 주의할 필요가 있습니다.

번역 결과는 원문의 의미를 기반으로 하지만 최종 문장의 단어 대부분을 클로드가 새롭게 선택하기 때문에 앤트로픽은 **클로드가 생성한 번역문에도 워터마크가 적용된다**고 설명하고 있습니다. 

또 하나 중요한 점은 워터마크가 완벽한 AI 판별기는 아니라는 것입니다.

앤트로픽의 워터마크 검출 결과가 의미하는 것은,

**“이 글이 클로드가 작성하는 과정에 관여했을 가능성”**

입니다.

다음 내용을 직접 증명하는 기술은 아닙니다.

| 워터마크로 알 수 있는 것 | 워터마크만으로 알 수 없는 것 |
|---|---|
| Claude가 관여했을 가능성 | 사람이 직접 쓴 비율 |
| 특정 생성 패턴의 존재 가능성 | 실제 저작자가 누구인지 |
| 긴 텍스트에서 Claude 관여 확률 | 다른 AI가 작성했는지 여부 |
| Claude 처리 흔적 | 사용자의 신원 |
|  | 사용한 Claude 계정 |
|  | 특정 회사·조직 |
|  | 특정 대화 내용 |

앤트로픽은 워터마크에 **사용자, 조직, 채팅을 식별할 수 있는 정보가 포함되지 않는다**고 설명합니다. 

즉 워터마크를 발견했다고 해서

“이 문서는 A회사 김모 씨가 8월 15일 클로드에서 작성했다”

와 같은 정보를 알아낼 수 있는 구조는 아닙니다.


## 더 큰 문제는 클로드 하나가 아니라 AI 업계 전체가 같은 방향으로 갈 수 있다는 점입니다

이번 사건을 단순히 **“앤트로픽이 이상한 기능을 넣어서 사용자가 떠난 사건”**으로만 보는 것은 전체 흐름을 놓칠 수 있습니다.

핵심은 EU AI법을 계기로 앞으로 생성형 AI 시장 전체에서 **AI 콘텐츠 표시 기술이 표준 기능으로 자리 잡을 가능성**이 커지고 있다는 점입니다.

EU 집행위원회는 2026년 8월 2일부터 AI법 제50조의 투명성 의무를 적용하고 있으며 AI 제공업체가 생성·조작된 콘텐츠를 탐지할 수 있도록 **기계 판독 가능한 표시**를 적용하는 방향을 제시하고 있습니다. 

앤트로픽도 자사의 방식만 특별한 것이 아니라 다른 주요 AI 사업자 역시 관련 투명성 규정에 대응하게 될 것이라고 설명하고 있습니다. 

따라서 장기적으로는 다음과 같은 변화가 나타날 가능성이 있습니다.

| 현재 | 앞으로 예상되는 변화 |
|---|---|
| AI 사용 여부를 사용자가 직접 밝힘 | AI 생성 여부를 기술적으로 확인 |
| AI 탐지기가 문체 분석 | 모델 자체 워터마크 활용 |
| 업체별 기술이 제각각 | 업계 표준화 가능성 |
| AI 생성 콘텐츠 중심 | AI 편집·가공 콘텐츠까지 논쟁 확대 |
| 사람이 AI 사용 여부 판단 | 시스템이 AI 관여 가능성 표시 |
| ‘AI가 썼나?’가 핵심 | **‘AI가 얼마나 관여했나?’가 핵심** |

이미 이미지 영역에서는 **C2PA(Content Credentials)**처럼 파일의 제작·편집 이력을 확인할 수 있는 표준이 확산되고 있습니다.

앤트로픽도 클로드가 PNG, JPG, SVG 등 지원 파일을 생성할 때 텍스트 워터마크와는 별도로 **C2PA 기반 콘텐츠 자격증명(Content Credential)**을 파일 메타데이터에 추가한다고 설명하고 있습니다. 

텍스트는 이미지보다 훨씬 복잡합니다.

이미지는 특정 파일 하나가 존재하지만 텍스트는 복사하고 붙여넣고 일부 문장을 고치고 다른 AI에 다시 입력하는 과정이 매우 쉽습니다.

실제로 앤트로픽 역시 텍스트를 충분히 많이 다시 작성하면 워터마크를 제거할 수 있다는 점을 인정하고 있습니다. 약간의 수정으로는 패턴이 남을 수 있지만 **전체 문장을 사실상 새롭게 다시 쓰면 기존 워터마크가 사라질 수 있습니다.** 

결국 기술적으로도 워터마크는 절대적인 ‘AI 감별 도장’이라기보다 **AI 관여 가능성을 판단하기 위한 하나의 신호**에 가깝습니다.

이 때문에 앞으로는 단순히 워터마크 기술을 도입하는 것뿐 아니라,

**AI 생성**
→ **AI 공동작성**
→ **AI 편집**
→ **AI 교정**
→ **AI 번역**
→ **AI 검토**

를 어디까지 같은 범주로 볼 것인지에 대한 사회적 기준이 필요해질 것으로 보입니다.


## 클로드 구독 취소 논란, 결국 AI 시대의 새로운 ‘사용 흔적’ 문제입니다

현재 상황을 종합하면 앤트로픽의 워터마크 논란은 기술적 결함 때문에 발생한 사건이라고 보기 어렵습니다.

오히려 **AI 투명성을 높이기 위한 기술이 실제 업무 환경의 복잡한 AI 사용 방식과 충돌하면서 발생한 문제**에 가깝습니다.

앤트로픽의 공식 설명과 실제 사용자들의 우려를 나란히 놓으면 차이가 뚜렷합니다.

| 앤트로픽의 설명 | 일부 사용자의 우려 |
|---|---|
| 워터마크는 보이지 않음 | 보이지 않기 때문에 오히려 불안 |
| 개인정보가 포함되지 않음 | AI 사용 여부 자체가 공개될 수 있음 |
| 결과물 품질 영향 없음 | 품질보다 업무 규정이 문제 |
| 단순 교정은 감지 어려움 | 조금이라도 표시될 가능성을 우려 |
| 코드에는 적용 빈도가 낮음 | 고객에게 전달되는 코드라면 위험 부담 |
| 저작권·소유권에는 영향 없음 | 계약이나 회사 정책 문제는 별개 |
| EU AI법 준수를 위한 조치 | EU 밖 사용자까지 적용되는 데 불만 |

특히 앤트로픽은 현재 지역별로 안정적으로 워터마크 적용 범위를 구분하기 어렵다는 이유로 **출시 단계에서는 글로벌하게 적용하고 있다**고 밝혔습니다. 신규 모델부터 시작해 과도기를 거쳐 기존 모델에도 확대할 계획입니다. 

그러나 사용자 반발이 실제 사업에 얼마나 큰 영향을 주고 있는지는 조금 신중하게 볼 필요가 있습니다.

소셜미디어에서는 구독을 취소했다는 사례가 잇따라 등장했지만, 앤트로픽은 **워터마크 발표 이후 전체 구독 취소율이 증가하는 추세는 확인되지 않았다는 입장**을 밝혔습니다. 

따라서 현재 단계에서 이를 대규모 ‘클로드 탈퇴 사태’라고 단정하기보다는,

**전문 사용자 일부에서 강한 반발과 구독 취소 움직임이 나타나고 있으며 이것이 AI 워터마크 정책에 대한 중요한 시험대가 되고 있다**

정도로 보는 것이 가장 정확합니다.

그리고 이번 논쟁에서 가장 중요한 질문은 결국 하나입니다.

**AI가 글을 ‘작성한 것’과 사람이 작성한 글을 AI가 ‘도와준 것’을 같은 방식으로 표시해야 할까요?**

생성형 AI가 처음 등장했을 때는 사람이 질문하고 AI가 결과물을 통째로 만드는 방식이 일반적이었습니다.

하지만 2026년 현재 AI는 이미 워드프로세서의 맞춤법 검사나 IDE의 자동완성처럼 일상적인 생산성 도구로 빠르게 이동하고 있습니다.

사람이 95% 작성한 글에서 AI가 문장 몇 개를 수정한 경우와, AI가 처음부터 끝까지 작성한 글을 동일한 ‘AI 생성 콘텐츠’ 범주로 처리한다면 사용자 입장에서는 거부감이 생길 수밖에 없습니다.

반대로 AI 생성 콘텐츠가 사회 전반으로 확산되는 상황에서 아무런 표시 없이 AI 결과물이 유통된다면 **가짜 정보, 사칭, 자동 생성 콘텐츠, 여론 조작** 같은 문제를 통제하기 어려워질 수도 있습니다.

결국 앤트로픽의 클로드 워터마크 논란은 단순한 기능 업데이트 문제가 아닙니다.

**AI 투명성과 사용자 프라이버시, 규제 준수와 생산성, AI 생성과 AI 보조의 경계를 어디에 그을 것인가**

라는 생성형 AI 시대의 핵심 문제를 보여주는 사례라고 할 수 있습니다.

특히 개발자나 전문 문서 작성자라면 앞으로 사용하는 AI 서비스가 단순히 “성능이 좋은가”만 확인해서는 부족할 가능성이 높습니다.

**워터마크 정책, AI 생성물 표시 방식, 기업의 AI 사용 규정, 고객 계약, 코드 및 문서의 출처 증명 방식**까지 확인해야 하는 시대가 시작되고 있기 때문입니다.

2026년 AI 서비스 경쟁의 새로운 변수가 모델 성능이나 가격이 아니라 의외로 **‘AI를 사용했다는 흔적을 어디까지 남길 것인가’**가 될 수도 있습니다.
